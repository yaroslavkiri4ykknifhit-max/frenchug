# Интеграции: план, не работающий backend

Публичный сайт статичен и не принимает платежи. Никаких credentials в клиентском коде.

Будущий backend на Workers/D1:

- Telegram-бот связывает авторизованный Telegram ID с заказом. Подтверждение личности и подпись Telegram проверяются на сервере.
- Сервер создаёт счёт у поддерживаемого провайдера только после проверки допустимости продукта и платёжного сценария. Цена и срок берутся из серверной конфигурации.
- Webhook проверяет подпись и достоверность статуса у провайдера. События идемпотентны; redirect страницы оплаты не является доказательством платежа.
- D1 хранит идентификатор заказа, пользователя, провайдера, статусы, время начала и окончания доступа; invoice, payment, membership — отдельные состояния.
- При подтверждённой оплате backend выдаёт ограниченную по сроку invite-ссылку и фиксирует результат операции Telegram.
- Cron и повторяемая очередь отзывают доступ после окончания 30 дней или подтверждённого полного возврата. Нужны защита от двойной выдачи, повторные попытки и журнал ошибок.
- Рината подключается отдельно после определения границ доступа и правил обработки персональных данных.

Обязательные проверки до активации: повторный webhook, поддельная подпись, отменённый платёж, возврат, гонка двух событий, истечение подписки, сбой Telegram API. Только изолированные тестовые пользователи и тестовый режим провайдера до запуска. Никаких реальных сообщений клиентам при QA.
